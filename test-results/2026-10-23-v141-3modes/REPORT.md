## 판단

- **duplicate**: 30 Mbps 까지 손실 0, 경로 절단 거의 무손실. **50 Mbps 부터 하향 붕괴** — client 경로 보고에서 두 경로 owd 가 26/31 → 60 ms, jitter 38 ms 로 같이 늘었다(공통 지점의 큐잉).
  server multi-fec 이 코어 하나의 78~80%(단일 스레드)로 하향 처리가 밀린 것으로 본다. 60 Mbps 에서는 server 가 1초 넘게 묵은 하향 패킷 13,179개를 버렸다.
  VM 정지(샘플러 공백)는 없었다. 이전(2 vCPU) 같은 단계 8.6% 보다 나빠 — 1회 측정.
- **aggregate**: **40 Mbps 까지 손실 0.05% 이하**로 이번에는 duplicate 보다 높은 부하를 버틴다(회선·relay 부하 절반). 절단 손실 \~1% 는 이전과 같다(1초 검출 몫).
- **failover**: 손실 5% 경로(path[0])만 쓰므로 10 Mbps 부터 0.2~0.4% 가 남고 EAGAIN 이 가장 많다(경로 하나라 FEC 만으로 덮어야 하고 송신 창 여유도 경로 하나 몫).
  **활성 경로(path[0]) 절단 시 상향 1.8~1.9%** — 대기 경로로 넘어가기까지의 몫. 대기 경로(path[1]) 절단은 영향 없음.
- 셋 다 정상 동작(전환·복귀·복원). 처리 상한은 이 망에서 **duplicate \~40, aggregate \~40~45 Mbps**(각 방향), 다음 병목은 server multi-fec 단일 스레드.
