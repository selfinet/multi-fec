## 1. 왜 필요했나

기존 `aging_rt_*.py` 는 **서버 sink 도착분(업스트림)만** 본다. §19-가 결함은 "A 의 패킷이
B 의 경로로 나가고 B 가 conv 불일치로 조용히 버림" 형태라 **업스트림에는 나타나지 않는다.**

이 하네스는 **왕복**이라 하향을 직접 구동한다.

```
blaster_i ─▶ client_i ─mud─▶ [relay ×2] ─▶ server ─▶ echo ─▶ server ─▶ client_? ─▶ blaster_?
```

- 자기 태그 회수율 = 그 세션의 **하향 포함 전달률**
- 남의 태그 수신 = **오배송**

운영(:443) 무침습 **병렬 체인(:4443)**. netem 은 `:4443` 용 필터를 경로별 flowid 로 추가한다
(기본 필터는 dport 443 만 잡는다).

## 2. 실행

```bash
N=8 SECS=3600 MBPS=0.25 GW_BASE=37 ./mf_rt_multi.sh
```

`8세션 × 각 방향 0.25 Mbps × 3600초`, netem path[0] 25ms/5% · path[1] 30ms/2%.

## 5. ⚠️ 하네스 함정 2건 — 재사용 전 반드시 읽을 것

이 결과를 얻기까지 **세 번 실패**했고 둘 다 계측 도구 문제였다. 제품 결함으로 오진할 뻔했다.

### 5-1. 가드가 gw 를 1.6배 과대보고 (`mf_gwguard.sh`)

```bash
a=$(ssh $S "카운터")   # ssh 왕복 ~0.3s
sleep 1
b=$(ssh $S "카운터")   # ssh 왕복 ~0.3s
→ 실제 경과 1.6초인데 분모는 1
```

실제 19.4 Mbps 가 **31.5 로** 보였고 워치독이 허위 트립했다.
**수정**: 원격에서 두 시점과 경과시간을 모두 재고 실측 경과로 나눈다.

### 5-2. 워치독이 부모만 죽여 자식이 고아로 남음

`pkill -f "rt_multi.py"` 가 파이썬 부모만 죽였다. 자식 multi-fec 8개가 고아로 남아 리슨 포트를
계속 잡았고, `common.cpp:853` 의 **`SO_REUSEPORT`** 때문에 커널이 4-튜플 해시로 새 프로세스와
나눠 배분했다.

**증상이 제품 결함과 구분되지 않는다:**
- 세션 절반이 정확히 0%, 나머지 100% (부분 손실 아님)
- 실패 세션이 런마다 바뀜 (비결정적)
- 오배송 0 — 패킷이 사라진 것처럼 보임
- blaster→클라 패킷은 8포트 전부 균등 도착
- 그런데 실패 클라의 report 는 `original: 0 pkt`

**수정**: 워치독이 c·r·s 원격에서 자식까지 죽인다.

### 5-3. 연쇄와 교훈

```
가드 시간측정 버그 → 허위 트립 → 고아 발생 → SO_REUSEPORT 포트 분점
  → 세션 절반 침묵 (3런 오염) → 제품 결함으로 오인
```

**계측값이 예측과 크게 어긋나면 대상보다 계측 도구를 먼저 의심할 것.**
첫 트립에서 "예측의 1.45배" 를 규명하지 않고 레이트만 낮춰 재시도한 것이 세 번 헛돈 이유다.

### 5-4. 같은 증상 진단 순서

```
1. 리슨 포트를 누가 잡고 있나    sudo ss -unlp | grep <port>
2. 프로세스 나이와 -k 값         ps -o etime + /proc/PID/cmdline   ← 옛 키면 고아
3. 클라 report 의 original pkt   0 이면 소켓엔 오는데 못 읽는 것
4. tcpdump 로 포트 도달 확인
```
