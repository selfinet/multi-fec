# UDP GSO 송신 · GRO 수신 프로토타입 (2026-10-22~23, 테스트망)

브랜치 `perf/udp-gso` `9eb2a0e` (perf/syscall-batch 위, 미병합·미릴리스, **와이어 무변경**). `mud_lite.c` 만 바꿈:
- 송신: sendmmsg 묶음 안에서 같은 목적지·출발 주소(IP_PKTINFO)·크기의 패킷을 `UDP_SEGMENT` 메시지 하나로(마지막만 짧을 수 있음, 흐름별 순서 유지).
  커널이 거부하면 그 묶음을 하나씩 재전송하고 이후 끔.
- 수신: `UDP_GRO` + 64 KB 수신 버퍼 32개(2 MB), 세그먼트 단위로 쪼개 mud 에 넘김.
- `MF_UDP_GSO=0` / `MF_UDP_GRO=0` 으로 끔. 30초마다 `batch` 통계 로그.

## 검증 (sv1 루프백)

- 다운스트림 24 케이스 GSO 켬·끔 각 3회 전부 24/24, RNLC 9/9, 라우팅 9/9, 경로손실 10/10, FEC 경계 7/7.
- **1.4.0 혼용**(client GSO↔server 1.4.0, 반대, 양쪽 GSO, 양쪽 1.4.0) × 크기 고정·혼합: 8조합 왕복 100%, 역순 0.
- ASAN+UBSAN 오류 0(빌드 경고 1건은 upstream `lib/fec.cpp`, perf 브랜치도 같음).

## 판단

GSO·GRO 는 의도대로 동작하고(스택 통과 절반) 1.4.0 과 섞어도 문제없지만 **CPU 절감은 0~4%p 로 잡음 범위와 겹친다.**
이유: 묶음당 2.5 패킷으로 작고, VM NIC 이 `tx-udp-segmentation: off` 라 커널이 장치 직전에 소프트웨어로 다시 쪼개며,
드라이버·WG 암호화·softirq 비용은 패킷마다 그대로다. J1900 지사 상한(~15 Mbps)을 올릴 근거로는 부족하다 — 단독 릴리스 비권장.

## 부수 발견 — duplicate 에서 서버 하향이 "늘 늦는 무손실 경로" 를 쓰지 않는다 (1.4.0 부터, 미수정)

서버는 **데이터를 받은 경로에만** 세션 태그를 붙이는데(`mf_server.cpp` `mud_io_cb` → `peer_tag_path`), duplicate 에서 늦게 온 사본은
dedup 으로 `mud_recv()` 가 0 을 돌려 태그되지 않는다. 그 경로가 손실 없이 항상 늦으면 하향 데이터에서 영영 빠진다.
루프백(경로 지연 같음, path[0] 먼저 송신): client path[1] rx = v1.4.0 589 · perf 482 (probe 뿐) / path[0] ~60,000.
테스트망은 path[0] 5% 손실 때문에 path[1] 사본이 먼저 오는 일이 있어 태그되고 가려진다(10-22 path[1] rx ≈ path[0]).
