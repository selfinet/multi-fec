# duplicate 에서 서버 하향이 "늘 늦는 무손실 경로" 를 쓰지 않던 문제 (2026-10-23)

브랜치 `fix/dup-path-tag` `028dbed` (`fix/mud-rate-agg` 위 = 1.4.1 후보, 미릴리스). **서버 단독 수정, 와이어 무변경.**

## 원인

서버는 데이터가 도착한 경로에만 세션 태그를 붙이고(`mud_io_cb` → `peer_tag_path`), 하향은 그 세션의 태그된 경로로만 보낸다(§19-가).
duplicate 에서 늦게 온 사본은 dedup 으로 `mud_recv()` 가 0 을 돌려 데이터로 세지지 않는다 → **손실 없이 항상 늦는 경로는 영영 태그되지 않아
하향 데이터에서 빠진다** — 하향 이중화가 실제로는 한 경로. 손실이 있으면 늦은 경로 사본이 가끔 먼저 와서 태그되므로
테스트망(path[0] 5%)에서는 가려졌다. 1.4.0 이전부터 있던 동작(§19-가 태깅 도입 이후).

## 수정

dedup 표 항목에 첫 사본이 온 경로의 `peer_id` 를 함께 저장하고, 중복으로 버릴 때 `mud_get_last_dup_peer()`(신설)로 알린다.
서버는 `mud_recv()==0` 이면서 이 값이 있으면 그 사본의 실제 출처(`mud_get_last_remote`) 경로를 같은 세션에 태그·기록한다(`session_tag_duplicate`).
